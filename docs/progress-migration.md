# Что происходит со старым прогрессом

Коротко: **ничего не теряется**. Сайт продолжает писать в тот же самый ключ,
что и раньше, а перед первым запуском новой версии снимает резервную копию.

## Ключи в localStorage

| Ключ | Что внутри | Изменился? |
|---|---|---|
| `bishun_hsk30_progress_v1` | учебный прогресс | **нет**, тот же самый |
| `bishun_hsk30_admin_edits_v1` | правки словаря | **нет**, тот же самый |
| `bishun_hsk30_progress_backup_v1` | копия прогресса на момент обновления | новый |
| `bishun_hsk30_migration_v2` | отметка о миграции | новый |
| `bishun_hsk30_sync_queue_v1` | очередь неотправленных событий | новый |
| `bishun_hsk30_device_v1` | идентификатор устройства | новый |
| `bishun_hsk30_audio_v1` | настройки звука | новый |

Ни один старый ключ не переименован и не удаляется.

## Что делается при первом открытии новой версии

1. Читается `bishun_hsk30_progress_v1`.
2. Если он есть и копии ещё нет — содержимое целиком складывается в
   `bishun_hsk30_progress_backup_v1` вместе с датой.
3. В `bishun_hsk30_migration_v2` пишется отметка:
   `{ id, at, hadLegacy, backedUp, legacyKey, syncedToServer }`.
   Отметка ставится один раз — при следующих запусках она не перезаписывается,
   поэтому импорт не повторяется.
4. Старая форма данных приводится к новой: добавляются поля `settings`,
   `lastLevel`, `lastChar`, `updatedAt`. Существующие числа повторений,
   счётчики и дни занятий остаются как были.

Старый ключ **не удаляется никогда** — ни после входа в аккаунт, ни после
успешной синхронизации. Он и есть боевой ключ.

## Что происходит при первом входе в аккаунт

1. Локальное состояние целиком уходит на сервер одним событием типа `snapshot`.
   Событие отмечается флагом «этот аккаунт с этого устройства уже выгружен»,
   поэтому повторно не отправляется.
2. Сервер сливает снимок с тем, что уже есть в аккаунте.
3. Итоговое состояние возвращается и сливается с локальным ещё раз — уже в
   браузере, тем же алгоритмом.
4. В отметке о миграции проставляется `syncedToServer: true`.

## Правила слияния

Одинаковые и в браузере (`js/progress.js`), и на сервере
(`public.apply_progress_events`):

* **повторения каждого знака** — берётся наибольшее значение.
  Если на телефоне 安 написан 5 раз, а на ноутбуке 2 — останется 5;
* **общее число написаний и число написаний без ошибок** — растут на дельту
  каждого события, а снимок может только поднять их до присланного итога,
  уменьшить — нет;
* **дни занятий** — объединяются, дубликаты убираются, порядок сохраняется;
* **последняя сессия, последний уровень и знак, настройки** — берутся из более
  свежего события по времени;
* **повторная отправка того же события ничего не меняет** — идентификатор
  события является первичным ключом таблицы `progress_events`.

## Почему прогресс не сбрасывается

* **перезагрузка страницы** — данные читаются из localStorage, ключ прежний;
* **обновление Service Worker** — при активации чистятся только кэши,
  начинающиеся с `bishun-`; localStorage сервис-воркер вообще не трогает
  (это проверяется автотестом);
* **вход в аккаунт** — локальное состояние сливается с серверным, а не
  заменяется им;
* **выход из аккаунта** — `signOut()` завершает сессию и всё; локальные ключи
  остаются нетронутыми;
* **приватный режим Safari** — запись в localStorage бросает исключение,
  поэтому обёртка `js/storage.js` держит данные в памяти сессии и один раз
  пишет предупреждение в консоль вместо падения.

## Ручное восстановление

* **Прогресс → «Восстановить из резервной копии»** — сливает копию,
  снятую при обновлении, с текущим состоянием (по максимуму, ничего не теряя).
* **Админ → «⇩ Копия»** — выгружает файл с прогрессом и правками словаря.
* **Админ → «⇧ Импорт»** — принимает такой файл. Импорт тоже **сливает**,
  а не затирает: по каждому знаку берётся большее число повторений.
