# Памятка администратора

## Вход

**Админ** в шапке → поле «Пароль администратора» → ваш пароль (`2007`) → **Войти**.

Проверка происходит на сервере. В файлах сайта нет ни пароля, ни его хеша,
ни кода сравнения — подобрать четыре цифры, глядя в исходники, невозможно.
После пяти неверных попыток вход блокируется на 15 минут для этого адреса.

Сессия живёт 4 часа и хранится в `sessionStorage`: при закрытии вкладки
она пропадает. Кнопка **«Закрыть»** завершает её сразу.

## Что можно делать

| Действие | Как |
|---|---|
| Найти слово | поле «Найти слово для изменения» — по иероглифам, пиньиню или переводу |
| Изменить слово | нажать на найденное слово, поправить поля, **Сохранить** |
| Добавить слово | **＋ Добавить**, заполнить уровень, иероглифы, пиньинь, часть речи, перевод |
| Отменить изменение | открыть слово → **«Отменить это изменение»** (базовое слово вернётся к официальному) |
| Удалить своё слово | открыть его → **«Удалить пользовательскую запись»** |
| Сохранить копию | **⇩ Копия** — файл с прогрессом и всеми правками |
| Загрузить копию | **⇧ Импорт** — правки восстанавливаются, прогресс **сливается**, а не затирается |

## Где живут правки

* **Supabase настроен** — правки уходят на сервер в таблицу `dictionary_edits`
  и после обновления страницы видны всем посетителям. Под карточкой написано
  «Правки сохраняются на сервере и видны всем».
* **Supabase не настроен** — правки остаются в браузере
  (`bishun_hsk30_admin_edits_v1`). Надпись честно говорит об этом.

Записывать в `dictionary_edits` может только Edge Function `admin-edits`,
и только предъявив действующую серверную сессию администратора. Из браузера
напрямую таблицу изменить нельзя — это запрещено политиками RLS.

## Смена пароля

Файлы сайта менять не нужно.

1. Посчитайте новый хеш:

   ```bash
   printf '%s' "НОВЫЙ-ПАРОЛЬВАША-СОЛЬ" | sha256sum
   ```

2. **Supabase → Project Settings → Edge Functions → Secrets** → замените
   `ADMIN_PIN_HASH`.

Новый пароль действует сразу. Соль (`ADMIN_PIN_SALT`) при этом менять
необязательно, но если поменяете — пересчитайте хеш с новой солью.

## Управление аудио

* **Статический пак.** Собирается один раз на вашем компьютере:

  ```bash
  node tools/generate-audio.mjs --engine edge
  ```

  Скрипт положит mp3 в `audio/n` (обычная скорость) и `audio/s` (медленная)
  и обновит `audio/manifest.json`. Уже готовые файлы пропускаются, поэтому
  запуск можно прерывать и повторять. Нужен `pip install edge-tts`.

  Чтобы добавить озвучку всех 11 000 слов, а не только знаков и примеров:

  ```bash
  node tools/generate-audio.mjs --engine edge --scope all
  ```

* **Сервер.** Если задан `TTS_PROVIDER` и ключ провайдера, слова, которых нет
  в статическом паке, озвучиваются через Edge Function и складываются в
  Supabase Storage — второй раз то же слово провайдер уже не синтезирует.

* **Порядок источников** всегда такой: статический пак → сервер → голос
  браузера. Последний — только аварийный запас.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| «Проверка администратора выполняется на сервере» и кнопка неактивна | заполните `supabaseUrl` и `supabaseAnonKey` в `js/config.js` |
| «Сессия администратора истекла» | войдите заново, сессия живёт 4 часа |
| «Слишком много попыток» | подождите 15 минут либо очистите таблицу `admin_attempts` в Supabase |
| Правка сохранилась локально, но не на сервере | посмотрите логи функции `admin-edits` в Supabase → Edge Functions |
